# フェーズ4 ランク戦とマッチング

世界中のプレイヤーと、レートの近い相手でランク戦ができるようにしました。

**次に進む条件**：50人規模のテストで、待ち時間が平均30秒以内。

## 入っているもの

- メニューに「ランク戦」ボタン。自分のランク（例：ゴールド II）、レート、勝敗、地域を表示
- 待ち画面に、待ち時間と今の探し方（例：「23秒 レート差 ±150・同じ地域」）を表示。90秒待つと「Botと対戦する（レートは変わりません）」が出る
- 試合後に、レートの変化（例：「レート 1218 → 1238（+20）」）と、ランクが変わったらその表示
- 「ランキングを見る」で、世界と自分の地域の上位10人
- 試合を途中で抜けたら負け扱い。3回抜けるごとに、10分間ランク戦に参加できなくなる
- 「オンライン対戦」は「カジュアル戦」に名前を変えた（レートは変わらない）
- タイトルを「SUPER BATTLE PING-PONG!!」に変更

## ルール（`src/shared/Rank`）

| 項目 | 内容 | 場所 |
| --- | --- | --- |
| 初期レート | 1000 | `Rating.INITIAL` |
| レートの増減 | 同じ強さの相手に勝つと+20。格上に勝つほど多く、最小8・最大36 | `Rating.delta` |
| 最初の10試合 | 増減が2倍（早く本来のランクに落ち着かせる） | `Rating.PLACEMENT_GAMES` |
| ランク | ブロンズ（〜1099）、シルバー（1100〜）、ゴールド（1300〜）、ダイヤ（1500〜）、マスター（1750〜）。マスター以外は III・II・I に分かれる | `Rating.tier` |
| リフトレジェンド | 地域ランキングの上位100人 | `Leaderboard.isLegend` |
| シーズンの切り替え | レートを1000から70%の距離まで戻す。`PlayerData.SEASON` と `Leaderboard.SEASON` を1つ上げると次に読み込んだときに適用 | `Rating.seasonReset` |
| 地域 | 北米・南米・ヨーロッパ・アジア・オセアニア。Robloxが返す国から決める | `Regions` |

### 対戦相手の選び方（`Matchmaker`）

| 待ち時間 | 許すレート差 | 許す地域 |
| --- | --- | --- |
| 0〜10秒 | ±50 | 同じ地域 |
| 10〜30秒 | ±150 | 同じ地域 |
| 30〜60秒 | ±300 | 隣の地域も |
| 60秒以上 | 制限なし | どこでも |

長く待っている人から順に、条件に合う中で一番レートの近い相手と組みます。条件は、2人のうち長く待っている方の待ち時間で決めます。

## 仕組み

```
ロビーのサーバー（どれでも）
  ランク戦を押す → 自分のサーバーの待ち一覧に入る
  1秒ごと：
    自分の待ち一覧を MemoryStore の共通の待ち行列に書く（30秒ごとに更新、2分で自動で消える）
    10秒の「鍵」を取れたサーバーだけが、全員の待ち行列から組み合わせを作る
      → 組ごとに TeleportService:ReserveServer で専用サーバーを予約
      → 専用サーバー用に「誰が来るか」を MemoryStore に書く
      → 2人それぞれに「行き先」を書く
    自分のサーバーの人に「行き先」が届いていたら、その専用サーバーへテレポート

専用サーバー（ランク戦の部屋）
  「誰が来るか」を読む → 2人そろったら試合開始（40秒たっても来なければ中止、レートは変わらない）
  試合が終わったら：レートを計算して DataStore に保存、ランキングを更新、結果を表示
  12秒後に全員をロビーへ戻す
```

| ファイル | 役割 |
| --- | --- |
| `src/server/PlayerData.luau` | レート・勝敗・抜けた回数を DataStore に保存。UpdateAsync で書くので、複数のサーバーが同時に書いても壊れない |
| `src/server/Leaderboard.luau` | 世界と地域のランキング（OrderedDataStore）。読み込みは1分間キャッシュ |
| `src/server/RankedQueue.luau` | 待ち行列（公開されたゲームでは MemoryStore、Studio ではサーバーの中だけ） |
| `src/server/RankedRoom.luau` | ランク戦の専用サーバーの進行 |
| `src/server/RankedResult.luau` | 試合後のレート計算・保存・結果の通知 |

## Studio で試す

Studio ではテレポートができないので、**同じサーバーの中で**ランク戦の相手を探します（レートや保存の仕組みは本番と同じ）。

1. Studio の「ゲーム設定」→「セキュリティ」で「**API サービスへの Studio アクセスを有効にする**」をオンにする（成績を DataStore に保存するため。オフでも遊べるが、成績はそのセッションの間だけ）
2. 「テスト」→「クライアントとサーバー」でプレイヤー2人で開始
3. 2人とも「ランク戦」を押す
4. 試合後、レートの変化が出る。メニューのランク表示と「ランキングを見る」にも反映される

## 公開して試す（サーバーをまたぐマッチング）

サーバーをまたぐマッチングとテレポートは、ゲームを公開しないと動きません。

1. ゲームを Roblox に公開する（非公開のままでも、テスト用の友達を招待すれば動く）
2. 「ゲーム設定」で、API サービスを有効にする
3. 2人以上で別々に参加し、「ランク戦」を押す
4. 「対戦部屋へ移動しています…」と出て、2人が同じ専用サーバーに移り、試合が始まる

50人規模のテスト（次に進む条件）は、Discord などで人を集めて行います。

## 自動テスト

| ファイル | 内容 |
| --- | --- |
| `tests/Rank.spec.luau` | レートの増減、ランクの区切り、シーズンの切り替え、国と地域、待ち時間による条件の広がり、組み合わせの作り方 |
| `tests/Smoke.spec.luau` | Studio と同じ「サーバーの中だけ」の方法で2人が組まれ、試合をして、両方のレートが保存され、ランキングに載ること。公開時と同じ方法で、別サーバーの人と MemoryStore を通して組まれ、テレポートされること。専用サーバーが2人そろってから試合を始め、途中で抜けた人に負けと「抜けた回数」が記録されること |

DataStore・MemoryStore・テレポートは、テスト用の偽物で動かしています。本物の Roblox サーバーで動くかどうかは、公開してから確かめる必要があります。

## まだできていないこと

- 通信の往復が250msを超える相手を避ける仕組み（仕様書の「なるべく当てない」）
- フレンド対戦（招待コード）
- ランキングをロビーに大きく飾る表示（今はメニューから開く画面のみ）
- シーズン報酬の配布
